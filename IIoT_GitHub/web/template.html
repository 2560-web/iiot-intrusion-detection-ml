03 / Understanding the experiment
What went into the result?
Measurements the forest used most
Training-set impurity importance describes this fitted forest. It does not prove causation and may favour high-cardinality measurements.
Checks that make the evidence useful
  • Attack labels and attack-type annotations never enter the model.
  • Raw hosts, timestamps, topics and payload strings are excluded.
  • Identical numeric input vectors stay on one side of the split.
  • The imputer learns from training rows only.
  • A majority baseline and TCP-only comparison use the same held-out rows.

04 / The limits matter
What this experiment can tell us.
01 / Scope
This is an offline binary traffic classifier on one public testbed dataset. It has not been validated on another industrial site or deployed as a live intrusion detector.
02 / Generalisation
Exact duplicate control helps, but similar sessions, protocol fingerprints and capture conditions can still inflate scores. The next useful test is a separate capture or site.
03 / Energy
The original dissertation explored an energy-related question. This rebuild measures classification and execution time. Without power measurements, it makes no energy-saving claim.
Original work and reconstruction
The original MSc report describes Random Forest, feature engineering, an 80/20 split and perfect scores. This package preserves the original source messages, assembles a runnable historical workflow, and adds a separate evaluation with duplicate controls, a narrower feature set and a demo. The original pasted code and outputs were recovered. The historical run reproduces the row counts and confusion matrix, while the notebook binary and exact execution state remain unavailable. All assembly changes are documented.
Dataset: Ferrag et al., Edge-IIoTset (IEEE Access, 2022). Research paper · Author's dataset page
